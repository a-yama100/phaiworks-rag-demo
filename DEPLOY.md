# Deploying

The demo is two deployments: a Python backend that holds every provider key, and the
Next.js frontend on Vercel that proxies to it and holds none.

> **Do the backend first.** Vercel auto-deploys from `main` (see `vercel.json`), so
> pushing the frontend before the backend exists replaces the current error with a
> different one — the site would go from "Retrieval failed" to "Could not reach the
> retrieval service". Nothing is gained until the backend answers.

---

## 1. Backend → Render

The repository contains `render.yaml`, so this is a Blueprint deploy rather than a
hand-configured service.

1. Render dashboard → **New → Blueprint** → connect `a-yama100/phaiworks-rag-demo`,
   branch `main`.
2. Render reads `render.yaml` and prompts for the two secrets marked `sync: false`:
   - `PINECONE_API_KEY` — the new key, also saved at `D:\SoftWare\API\Pinecone API key.txt`
   - `GOOGLE_API_KEY` — same value as the sites use, in their `.env.local`
3. `BACKEND_API_KEY` is generated by Render. **Copy it** — Vercel needs the same value in
   step 2. Render → the service → Environment shows it.
4. Deploy. The build is the Docker image in `api/Dockerfile`; expect a few minutes for the
   first one, since it installs the whole LangChain tree.

Check it before going further:

```bash
curl https://<your-service>.onrender.com/health
```

Expected: `{"ok":true,"briefs":52}`. If `briefs` is 0, the image did not pick up `data/` —
the build context has to be the repository root, which is what `dockerContext: .` sets.

### One decision to make: the free plan sleeps

`render.yaml` specifies `plan: free`, which spins down after inactivity and takes roughly
50 seconds to wake. That is fine while nobody is looking at it and wrong for a link on a
job application — a reviewer gives a demo about fifteen seconds before deciding it is
broken. Move the service to the paid tier before the URL goes anywhere.

## 2. Frontend → Vercel

Environment variables on the `rag-demo` project (Settings → Environment Variables):

| Action | Variable | Value |
|---|---|---|
| add | `BACKEND_URL` | `https://<your-service>.onrender.com` — no trailing slash |
| add | `BACKEND_API_KEY` | the value Render generated in step 1 |
| delete | `PINECONE_API_KEY` | the frontend no longer talks to Pinecone, and this is the revoked key |
| delete | `PINECONE_INDEX` | now backend-side |
| delete | `MIN_SCORE` | now backend-side, and the frontend value is stale |

Deleting the first three is the point of the rework: after this the Vercel deployment has
no AI credential in it at all.

Then ship the frontend:

```bash
git checkout main
git merge feat/langgraph-agent-eval
git push origin main
```

Vercel builds on push. Commit author must be `yama0226@gmail.com` or the deployment is
blocked — do not override the author.

## 3. Verify

```bash
curl -s https://rag-demo.phaiworks.com/api/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"the iron test that is not thrown off by inflammation"}'
```

Expected: `refused: false`, an answer citing `BRIEF-TRANSFERRIN-SATURATION-001`, and a
`trace` array. Then in a browser:

- `/` — ask an out-of-scope question ("what dose of levothyroxine should I take") and
  confirm it declines with `model_declined` and shows the trace
- `/evals` — confirm the measured numbers render, not the "not run" placeholder

If `/api/ask` returns 502, the backend is unreachable or the shared secret does not match:
Vercel's `BACKEND_API_KEY` and Render's must be identical. The real cause is in the Vercel
function logs — the browser deliberately only ever sees a generic message.

## 4. Re-running the eval

The published numbers come from a run against the live index. To refresh them:

```bash
cd api
.venv/Scripts/python.exe eval/run_eval.py --sweep --sweep-weights --with-generation
```

This overwrites `public/eval-results.json`; commit it and push to update `/evals`. It
makes real API calls — retrieval is fractions of a cent, `--with-generation` is roughly
$0.05.

If the corpus changes, re-ingest first (`python ingest.py`), which only re-embeds briefs
whose content hash changed.

---

## Rollback

The frontend rolls back from the Vercel dashboard (Deployments → an earlier one →
Promote). The backend rolls back from Render (Events → Rollback). The Pinecone index is
unaffected by either, and `ingest.py` is idempotent, so re-running it is always safe.
